# ONePay — лендинг для скачивания (Android)

Реализация ТЗ `TZ_LANDING.md` (см. корень репозитория). Статический сайт — HTML/CSS/JS без сборки,
разворачивается копированием файлов на любой веб-сервер с HTTPS.

## Структура

```
landing/
├── index.html              — сама страница
├── styles.css
├── app.js                  — подтягивает version.json, подставляет версию/дату/ссылку
├── version.json             — метаданные последней версии (см. ниже)
├── assets/
│   ├── icon.png
│   └── screenshots/         — скриншоты интерфейса + разрешения "неизвестные источники"
└── download/                 — сюда кладутся сами APK-файлы (см. ниже), в репозитории её нет
```

## ⚠️ Что нужно сделать перед первым релизом (не сделано мной — нет доступа к серверу)

1. **Определиться с адресом.** Сейчас во всех файлах зашита заглушка `https://app.oneads.me` —
   это пример из самого ТЗ, а не реальный домен. Нужно заменить на настоящий:
   - `landing/version.json` → поле `apk_url`
   - `app/build.gradle.kts` → `UPDATE_CHECK_BASE_URL` (см. ниже, это Android-часть)
2. **Выложить файлы на сервер** (nginx, тот же, что бэкенд/админка) — папку `landing/` целиком,
   под HTTPS.
3. **Собрать и загрузить первый APK** в `landing/download/` (см. "Как выпускать новую версию").

## Как выпускать новую версию (ручной процесс, как написано в ТЗ §5)

1. В Android-проекте поднять версию в `app/build.gradle.kts`:
   ```kotlin
   versionCode = 2       // +1 к предыдущему, обязательно
   versionName = "1.1.0" // semantic versioning
   ```
2. Собрать release APK, назвать с версией в имени, например `onepay-1.1.0.apk`.
3. Загрузить файл на сервер в `download/`, рядом сохранить/обновить копию
   `download/onepay-latest.apk` (стабильная ссылка — см. ниже, зачем).
4. Обновить `version.json` на сервере:
   ```json
   {
     "latest_version": "1.1.0",
     "latest_version_code": 2,
     "min_supported_version_code": 1,
     "apk_url": "https://ваш-домен/download/onepay-1.1.0.apk",
     "updated_at": "2026-11-01",
     "changelog": "Что изменилось — коротко, видно пользователю в блокирующем экране обновления",
     "force_update": false
   }
   ```
   - `min_supported_version_code` поднимайте только если старые версии реально сломаны (например,
     после breaking-изменения в API) — именно это поле заставляет пользователей обновиться
     принудительно (блокирующий экран в приложении).
   - `force_update: true` — то же самое, но без привязки к версии: разово заставить всех обновиться
     прямо сейчас, независимо от `min_supported_version_code`.
5. Готово — у всех, кто откроет приложение, при следующем запуске появится баннер (или блокирующий
   экран, если подняли `min_supported_version_code`/`force_update`).

### Про `download/onepay-latest.apk`

Кнопка "Скачать" на лендинге (`app.js`, `FALLBACK_APK_URL`) по умолчанию ссылается на
`download/onepay-latest.apk` — стабильный путь, который не меняется от релиза к релизу. При каждой
выкладке **перезаписывайте этот файл** копией последнего APK (или делайте симлинк на сервере на
актуальный файл) — тогда не придётся лезть в вёрстку `index.html` при каждом релизе. Сама кнопка
при наличии `version.json` всё равно подставляет точный `apk_url` из него — `latest.apk` это просто
подстраховка на случай, если `version.json` почему-то не загрузился.

## nginx — пример конфига (адаптируйте под свой сервер)

```nginx
server {
    listen 443 ssl http2;
    server_name app.oneads.me;  # замените на реальный домен

    ssl_certificate     /etc/letsencrypt/live/app.oneads.me/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.oneads.me/privkey.pem;

    root /var/www/onepay-landing;  # сюда скопирован landing/
    index index.html;

    location /download/ {
        # APK должен отдаваться с правильным MIME-типом, иначе некоторые браузеры
        # не предложат скачать/установить файл корректно.
        types { application/vnd.android.package-archive apk; }
        default_type application/vnd.android.package-archive;
    }

    location /version.json {
        add_header Cache-Control "no-cache";
    }
}
```

## Android-часть (уже сделана в этой сессии, живёт не в landing/)

Проверка обновлений встроена в сам Android-клиент:

- `app/build.gradle.kts` → `UPDATE_CHECK_BASE_URL` — **тот же домен**, что и лендинг, сейчас тоже
  заглушка `https://app.oneads.me/`, поменять вместе с `version.json`.
- `app/src/main/java/tj/onepay/app/presentation/update/` — вся логика: `UpdateCheckViewModel`
  (проверка при каждом запуске, сравнение `versionCode`), `UpdateRequiredScreen` (блокирующий экран),
  `UpdateBanner` (ненавязчивое напоминание).
- Недоступность `version.json` (нет сети, 404, сервер лёг) не ломает и не блокирует
  приложение — молча ничего не показывает, как и требует ТЗ §3.2.
- iOS сознательно не трогали — ТЗ прямо говорит, что iOS отложен отдельно.

## Чего ещё нет (честно, по ТЗ)

- **Реальные скриншоты "Chrome предупреждает о небезопасном файле"** — такое предупреждение
  появляется только при реальной загрузке APK с настоящего сервера, которого пока нет. Шаг 2 в
  инструкции на лендинге описан текстом без скриншота; добавьте скриншот после первого реального
  релиза, когда появится что скачивать.
- **Автоматизация релиза (CI)** — ТЗ прямо говорит, что для первого этапа это необязательно,
  процесс ручной (см. выше).
